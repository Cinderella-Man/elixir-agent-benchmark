# Source task audit

Reviewed 2026-10-11. This is a read-only audit supporting the planning interview, not a benchmark implementation or a decision about the final task set. No task, test suite, model inference, package installation or performance measurement was run.

This audit predates the accepted design and runnable pilot. Historical open choices below are superseded by the [design decisions](design-tree.md); actual execution is recorded in the [pilot evidence](pilot-results.md).

## Leakage and training exposure

The export contract explicitly identifies approximately 91.7% within-family text overlap: derived prompts embed parent modules, harnesses or near copies. It treats the first three-digit **idea number** as the atomic split group; grouping only by variation is insufficient. For example, the rate-limiter test-FIM prompt contains its working module and nearly all its tests; the adaptation prompt contains the working parent implementation. These are intentional training examples, not defects in the dataset. [Export contract](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/docs/16-export-contract.md), [test-FIM example](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/tasks/tfim_001_001_rate_limiter_02/prompt.md), [adaptation example](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/tasks/adapt_001_002_fixed_window_counter/prompt.md)

All inspected answers and graders are public. The repository is expressly intended for training, and its training handoff points to exported train/validation data. This establishes **possible exposure**, not proof that any named candidate was trained on it. Its reported decontamination against other public Elixir benchmarks does not make these tasks uncontaminated for evaluating models trained on this repository. [Training handoff](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/docs/18-training-run-handoff.md)

An agent given the complete original repository could read solutions, sibling prompts, exported completions, rejected attempts and diagnostic logs. A benchmark workspace boundary therefore needs an explicit design decision. Whether tasks are reused unchanged, adapted, or used only as inspiration remains open; this audit does not choose for the user.

## Grading and runtime facts

- The evaluator compiles a candidate and runs its harness. Multi-file evaluation materializes bundle files and adds generated Repo/Phoenix infrastructure according to the manifest. Its fresh BEAM process is execution isolation between tasks; the inspected code does not establish a filesystem/network security boundary against candidate code. [Runner](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/lib/eval_task/runner.ex), [scaffold generator](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/lib/eval_task/phoenix_kit.ex)
- The existing score is `0.7 × test fraction + 0.2 × static checks + 0.1 × compilation`, with zero for compilation failure, warnings, zero tests, or harness errors. Static checks include documentation/spec presence, line length, TODO markers and a SQL-interpolation heuristic; Credo is not scored. This is not automatically the desired agentic-quality score. Typespec FIM uses normalized AST equality, which is a different correctness notion from behavioral repair. [Scoring source](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/lib/eval_task/analysis.ex), [export shape contract](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/docs/16-export-contract.md)
- Exact toolchain file: **Elixir `1.20.2-otp-29`, Erlang `29.0.3`**. `mix.exs` declares a broader Elixir constraint, so it is not an adequate reproducibility pin alone. Dependencies include Ecto, SQLite/Postgrex, Phoenix/LiveView, Plug/Cowboy, Req, Explorer, Nx and ExUnit-related helpers; `mix.lock` exists. PostgreSQL is externally required for the documented search task. Compose uses a mutable `postgres:16-alpine` tag. [Toolchain](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/.tool-versions), [Mix project](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/mix.exs), [Compose](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/docker-compose.yml)
- Determinism is plausible for many behavior tests but not demonstrated by this read. The rate-limiter suite mostly uses a fake clock, yet its automatic cleanup test uses a real 25 ms timer and two 1,000 ms message deadlines. CI includes a temporary-path collision check, and project notes track flakes and prior gold/prompt defects. These are reasons for per-task validation, not grounds to declare the entire corpus flaky or defective. [Timer test](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/tasks/001_001_rate_limiter_01/test_harness.exs#L406), [CI](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/.github/workflows/validate.yml), [current source status](https://github.com/Cinderella-Man/elixir-sft-dataset/blob/328195bb34782b61fdad8df8188dffa86bc5defe/STATUS.md)
- GitHub metadata returned `license: null`, and the pinned root tree contains no license file. No explicit redistribution license was established by this bounded review. Ownership/permission and the license intended for the new published benchmark need recording. [Repository metadata](https://api.github.com/repos/Cinderella-Man/elixir-sft-dataset), [pinned root tree](https://api.github.com/repos/Cinderella-Man/elixir-sft-dataset/git/trees/328195bb34782b61fdad8df8188dffa86bc5defe)

## Hypotheses and unanswered choices

The OTP, database and multi-file tasks appear capable of supporting meaningful edit-run-debug episodes after packaging. That is a hypothesis requiring task design and validation; wrapping a one-function completion in terminal tools would not by itself establish realistic agentic difficulty.

The interview still needs to settle the work type and domains, starting-project scaffold, amount of public-task reuse, visible versus hidden tests, permissible tool feedback, correction policy for ambiguous tasks, success criteria, and treatment of related families. Other unresolved facts are candidate training exposure, actual gold/empty/broken-solution results at this pin, stability under the eventual environment, and the practical difficulty distribution. None has been inferred from the published unit count.
