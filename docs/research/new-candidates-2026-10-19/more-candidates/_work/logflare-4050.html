Summary

  • Stacked on feat: Unify broadcast and schema-update rate gating into one local sampler #4049.
  • Spool queue messages (SQS/PubSub) were acked as soon as their segments were handed off to Broadway, regardless of whether downstream pipelines had actually finished with the events inside them. Premature ack for non-pointer adaptors

SpoolAck.ack(spool_handle, 1) fires here as soon as the pointer row is claimed off the queue — not once the event has actually been processed.

claim_events/4 is reached via pop_pending, which is the fetch path BufferProducer.do_pop_key/2 uses for the non-pointer adaptors (webhook, syslog, http_based, postgres, s3). Unlike ClickHouse (clickhouse_adaptor/pipeline.ex) and BigQuery (bigquery/pipeline.ex), which call SpoolAck.ack only after their pipelines finish (success or terminal failure), none of these non-pointer adaptors were updated to ack on their own completion path. Their processing happens asynchronously in separate Broadway processor/batcher stages after this pop.

Concretely: a spool message routed only to Postgres (or webhook/syslog/http/s3) decodes to N events. Once all N are popped here, the count hits 0 and the real SQS/PubSub ack fires — before the Postgres insert (or webhook request, etc.) has actually completed. If that write then fails terminally, or the node crashes before it completes, the underlying queue message is already acked and the data is lost with no redelivery. This is the same class of premature-ack bug this PR is meant to fix (O11Y-2483), just for the non-pointer adaptors instead of ClickHouse/BigQuery.
