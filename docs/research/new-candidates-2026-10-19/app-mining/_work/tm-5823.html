Summary

Saving a geofence always re-assigned all drives and charging sessions inside it, twice (before and after the update), even when only its name, billing type or costs changed. On large databases, especially on a Raspberry Pi, this can take longer than the database timeout, so changing the price per kWh of a frequently used geofence failed and the form hung (#5818).

Drives and charging sessions reference a geofence only by its ID, and which geofence they belong to depends only on its latitude, longitude and radius. update_geofence/2 therefore skips the re-assignment when none of these three fields changed. Retroactively adding costs is unaffected: it selects charging sessions by their stored geofence_id, which stays correct as long as the location is unchanged.

Fixes #5818 for changes that keep the location and radius. Moving or resizing a geofence still re-assigns and can still exceed the timeout on such databases.

Behaviour change

Saving a geofence without changing its location or radius no longer re-assigns drives and charging sessions. Unlike before, such a save therefore no longer corrects existing wrong assignments, for example those left over from #5819.

Changes

  • elixir/lib/teslamate/locations.ex: update_geofence/2 runs apply_geofence/2 before and after the update only if latitude, longitude or radius changed; otherwise it only updates the geofence.

  • elixir/test/teslamate/locations/geofences_test.exs: two tests:

    • updating name and costs with all fields submitted as strings, as the form does, leaves drives and charging sessions untouched;
    • invalid data without a location change still returns an error changeset.

    Moving and resizing are already covered by the existing tests.

Testing

  • mix test test/teslamate/locations test/teslamate_web/live/geofence_live_test.exs: 149 passed; mix format --check-formatted clean. Only these files were run locally; CI runs the full suite.
  • Counter-check: forcing the re-assignment on every update fails only the new test "does not re-assign drives and charging processes if the location is unchanged".

Workarounds & open questions

None.
