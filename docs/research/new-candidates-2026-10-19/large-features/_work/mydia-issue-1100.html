I'm opening this discussion instead of an Issue ticket because Cardigann is still in an experimental state and I don't know what your plans or intentions are for it. I believe Cardigann is currently the only remaining part not working properly in Mydia concerning its "media manager" functionality.

I have tested the indexers that I've been using for a long time on Prowlarr, and they are the most popular public indexers.

Testing Process:

I tested every listed indexer separately using Prowlarr, and for context, they were all successful in returning results.
Then, I proceeded to test them using Cardigann with Prowlarr disabled.

Here are my findings:

Working Indexers:

  • LimeTorrents (doesn't need FlareSolverr) - Connects and shows results.
  • YTS (doesn't need FlareSolverr) - Connects and shows results.
  • Uindex (Needs FlareSolverr) - Connects and shows results.

Not working Indexers:

  • 1337x (needs FlareSolverr) - Connects, but doesn't show any search results.
  • EZTV (needs FlareSolverr) - Connects, but doesn't show any search results.
  • kickasstorrents.ws (needs FlareSolverr) - Connects, but doesn't show any search results.
  • kickasstorrents.to (needs FlareSolverr) - Connects, but doesn't show any search results.
  • Torrent Download (doesn't need FlareSolverr) - Connects, but doesn't show any search results.
  • The Pirate Bay (doesn't need FlareSolverr) - Doesn't connect, shows Error.

I’d like to highlight one important note.
When multiple indexers that rely on FlareSolverr are activated, only one manages to connect successfully, while the others fail and throw errors.

arsfeld
Oct 13, 2026
Maintainer

Thanks for reporting these Cardigann indexer problems and helping us track them down.

  • The Pirate Bay error is fixed now that the parser accepts the JSON array returned by its API.
  • The issue where 1337x, EZTV and kickass returned zero results through FlareSolverr because the definition's own headers and cookies were dropped is fixed.
  • To prevent Chrome tabs from crashing when running several FlareSolverr indexers at once, FlareSolverr now only solves the challenge, its clearance is cached and reused, and concurrency is capped.
  • A new HTML parser fixed Torrent Download and other public trackers that returned no rows, bringing working public definitions from 28 to 50 in a live sweep of 81.
  • Toggling an indexer off now disables it instead of removing it, and a separate Remove action keeps its settings.
  • LimeTorrents now shows the release page link.
  • Login works for every Cardigann login method, and captcha/2FA trackers get a "Log in" button.
  • There is a new opt-in "Prowlarr-based" engine where Prowlarr's own Cardigann code is compiled to WebAssembly and run inside Mydia with no Prowlarr server needed, switchable from Configuration > Indexers without a restart so definitions behave as they do in Prowlarr, with the drawbacks being a one-time download and compile that needs a lot of memory while it runs, higher memory usage, and slightly slower searches than the built-in engine.

arsfeld Oct 13, 2026
Maintainer

@t00n1x the prowlarr-based engine would act identically to prowlarr, so if something works in prowlarr, it would in theory work in mydia too. Something like LimeTorrents where the bug was on how Mydia acts, wouldn't happen. In practice I think it needs more testing now, because even though it's the same Prowlarr codebase, it's compiled to wasm and ran inside Mydia with our own interface, so there could be bugs. If it works well, it might be the only option in the future, otherwise we'll keep chasing individual tracker bugs.
