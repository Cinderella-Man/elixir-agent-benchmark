Fixes #1079.

A movie held in two Jellyfin libraries (say 1080p and 4K) is two Jellyfin
items with separate played flags. Mydia kept one mapping per movie, so the
mapping crawl kept whichever copy it listed last and every watch on the other
copy was dropped as "not found". That is why most 4K movies never picked up
their watched state.

  • Mappings are now one row per server copy. The migration moves uniqueness to
    (item, remote_id) and is reversible (rollback keeps the most recently seen
    copy per item).
  • A sync folds all copies of an item into one remote state: watched if any
    copy is watched, position from the most recently played copy.
  • An incremental run that only sees some of an item's copies assumes the
    unseen ones still hold the last agreed state, so it cannot unwatch a movie
    another copy has watched. Only a full listing can unwatch a multi-copy item.
  • Marking something watched or unwatched in Mydia writes to every copy. If any
    copy's write fails, no snapshot is recorded and the next run retries.
  • A forced mapping crawl prunes copies the server no longer lists. An empty
    crawl prunes nothing.

Unwatching only one copy in Jellyfin while another stays watched leaves the
movie watched; unwatch every copy, or unwatch in Mydia.

Existing installs pick up the missing copies on the next scheduled mapping
refresh; no manual step.

Verified locally on SQLite: full suite green, credo strict clean. Postgres is
covered by the CI job.

Summary by CodeRabbit

  • New Features
    • Sync now supports multiple remote copies of the same movie or episode. Watch status and playback progress are combined across copies, and local watch updates are sent to every copy.
  • Bug Fixes
    • Partial listings no longer clear a watched status reported by another copy.
    • Failed updates to any copy no longer record a successful sync.
    • Completed crawls remove mappings for copies no longer listed, while empty crawls leave mappings unchanged.
