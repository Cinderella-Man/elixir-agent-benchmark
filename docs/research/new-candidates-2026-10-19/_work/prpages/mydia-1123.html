Fixes #1120.

What broke

The Calendar's media type select had phx-change="filter" but no enclosing form. The LiveView client refuses form events from a control outside a form (pushInput throws "form events require the input to be inside a form"), so choosing Movies or TV Shows never reached the server. The server-side filter was fine all along. Phoenix.LiveViewTest.render_change does not check for an enclosing form, which is why tests never noticed.

Changes

  • Calendar: the select now sits in <.form id="calendar-filter-form" phx-change="filter">.
  • Admin > Users role filter: same defect, same fix (#users-role-filter-form). The search box and the role filter stay independent; each keeps the other's current value.
  • Removed two unreachable controls with the same defect:
    • the :select branch of the settings value control and its update_select_setting handler. No setting has used type: :select since 040cafc.
    • MetadataSearchForm, which had no callers, and its README section.
  • Guard test (test/mydia_web/form_controls_inside_forms_test.exs): scans every .heex file and ~H template under lib/mydia_web and fails on a select, input, textarea or <.input> with phx-change outside a form, naming the file and line. It fails on the pre-fix calendar template and passes on this branch.

Testing

  • New test/mydia_web/live/calendar_live_test.exs drives the filter through the form for both kinds, all, and back.
  • New role filter tests in admin_users_live_test.exs.
  • mix precommit.

Summary by CodeRabbit

  • Updates
    • Admin user and calendar filters now submit through forms. The available role and media-type options, selected values, and filtering behavior remain unchanged.
  • Removed
    • Removed the metadata search form, including its result suggestions and no-results prompt.
