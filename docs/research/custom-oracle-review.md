## Findings affecting interpretation

1. **Negative controls need the intended failure identity.** The reviewed runner accepts a negative variant when execution completes with any behavioral failure. That is insufficient when another assertion already fails on the reference. In particular, the [6300 plan](../../verification/task-quality/cases/plausible-pr-6300/audit.json) deliberately includes a DST reference challenge. If that challenge fails on both reference and mutant, it does not show that the hard-coded one-day mutation was detected. The retained evidence must show failure of the separate leap-year assertion, or another assertion specifically distinguishing that mutant from the reference. The same principle applies to preservation checks: a test that passes unchanged source is useful preservation evidence, not an additional reproduction of the original bug.

2. **A positive alternative requires original preservation as well as new checks.** The runner records `result.legacy_oracle.preservation` separately. At review time, its `expectation_met` field only used the final suite's `passed` value. A positive-control claim must also require successful original preservation; otherwise a purported valid alternative could break existing behavior that the final selected suite omits. The root audit is explicitly checking this dimension. The saved commands and stage results should establish the claim, not the convenience boolean alone.

3. **The actual runner command differs from the standalone command hints.** The `command` fields in several `audit.json` files are supplemental-only invocation hints. The reviewed runner does not read them: it executes the manifest acceptance command after applying either the original or replacement acceptance overlay, then appends `test_files`. Interpret results using that actual command. In particular, the 2663 alternative exercises original acceptance as well as the supplemental semantic test; the 2800 replacement changes the evaluator test assertions at the original test path.

## Remaining case checks

No additional concrete specification mismatch or clearly invalid mutation was found in the source review of the other eight plans. Their discriminating targets are appropriate: cross-team role scope (5939), supported imported-data preservation and page goals (6441), clearing malformed existing segment associations (6449), preserving supported aggregate time-on-page (6763), text/nested frame inputs and edited-value preservation (2219), Unicode byte offsets and non-Elixir executable insertions (2527), exact import preservation and failed dictionary rollback (2822), and S3 credential/connection failure paths (3076).

Several assertions intentionally preserve existing observable conventions rather than introducing new requirements: the stamp warning prefix exists in the starting import tests, evaluator contexts expose their fields through an already-tested API, and permission failures follow the starting LiveView access convention. Those facts reduce the concern that the custom checks invent hidden requirements. They do not eliminate the need to inspect actual named failures, ensure that setup completed, and verify reference/preservation results.

This review supports proceeding with the controls and reporting their precise outcomes. It does not support treating a failed reference challenge as a valid admitted fixture, a surviving mutant as automatically equivalent, or a supplemental-suite pass as sufficient evidence of a valid alternative.

## Follow-up evidence review

After the custom probes completed, the same separate review agent read their saved receipts and the coordinating report draft. It confirmed that all fifteen negative mutants had named behavioral failures that passed on their custom reference; the 6300 leap-year/east-of-UTC failures were distinct from its reference's DST failure. Both positive alternatives passed original preservation, with 2663 passing original acceptance and 2800 failing original acceptance while passing the semantic replacement. All twelve fresh seed-101 runs matched the original reference test-state maps. No material overclaim was found in the reviewed draft's completed conclusions; pending full-grader results were excluded from that judgment. The final full-grader outcomes are recorded in the [execution report](../verification/task-quality-audit-2026-10-14.md). This was a read-only evidence review, not a human attestation or a new execution run.

A later 2663 challenge tried adding a continuation space to every multi-digit parent. Source review regarded it as a plausible equivalent format, conditional on the actual parser. Execution disproved that assumption: Earmark retained an extra leading space inside fenced-code contents, and the semantic AST assertion failed. The source reviewer accepted that correction; the suggested replacement overlay was not promoted. This candidate is distinct from the passing boundary-only alternative and is not counted as a valid positive control or a false negative.
