# New network-client project candidates — 2026-10-18

This source-only pass adds **four new projects and four coordinated candidates**: Req, Mint, Finch and Tesla. Their task families differ: error propagation, protocol serialization, process lifecycle and opt-in secret handling. Mint's tunnel identity repair supplies a focused reserve. These are candidates for drafting and functional qualification, not admitted cases or measured difficulty claims.

The review used the repository's [selection guidance](../pr-selection-guidelines.md), [admission contract](../case-admission.md), [earlier exclusions](new-case-candidates-2026-10-18.md#do-not-rediscover-or-relabel-the-old-decisions) and previous project research. None of the four projects was in the earlier candidate cohort. Existing rejected and deferred sources retain their dispositions. No builds, dependency installation, tests, model attempts, speed measurements or patch-composition experiments ran for this report.

## Tesla #939: explicit secret values across inspection and middleware

**Draft clarified feature brief:** “Add an opt-in `Tesla.SecretString.new/1` value whose contents are hidden by normal inspection, including when nested in client middleware options. Converting it to a string must recover the value. Wrapped header values, bearer tokens and basic-auth passwords must still produce their original request credentials; ordinary strings must keep working.” Naming the public constructor is part of the feature contract, not a hint about a hidden implementation requirement.

The maintainer discussion specifically chose explicit wrapped values over globally guessing which client options are sensitive. The requested boundary is meaningful: `Inspect` and `String.Chars` have different responsibilities, and the Headers middleware must unwrap the value before sending it. This is not a promise to redact arbitrary logs or all in-flight request headers. [Discussion](https://github.com/elixir-tesla/tesla/pull/939).

The implementation changes `lib/tesla/secret_string.ex` and `lib/tesla/middleware/headers.ex`. BasicAuth and BearerAuth already interpolate credentials, so their existing executable code accepts the new protocol implementation. Four test files cover the wrapper and three middleware paths; a guide and two module documentation edits explain use. [Accepted diff](https://github.com/elixir-tesla/tesla/commit/258d37844c4fdb2efb22893f5ff9c07105cfa487).

**Proposed acceptance and preservation:** inspect several distinct secrets directly and nested in maps/lists, a client and a response-shaped env carrying that client; assert none appears, without requiring exact display punctuation. Independently inspect an ordinary nonsecret option so redacting the entire client cannot pass. Exercise Headers, BearerAuth and BasicAuth and assert the original bytes reach the adapter boundary. Preserve ordinary string credentials, unrelated headers and explicit `to_string/1` behavior. Do not demand that inspecting an env after middleware has placed real credentials into `env.headers` hides those bytes: the upstream scope explicitly excludes that scenario. [Wrapper tests](https://github.com/elixir-tesla/tesla/blob/258d37844c4fdb2efb22893f5ff9c07105cfa487/test/tesla/secret_string_test.exs), [Headers implementation](https://github.com/elixir-tesla/tesla/blob/258d37844c4fdb2efb22893f5ff9c07105cfa487/lib/tesla/middleware/headers.ex).

**Plausible incomplete controls:** implement redacted inspection but leave wrapped Headers values on the request; alternatively convert everything to a redacted string, losing usable credentials. Both can compile and should fail named functional checks. They have not been constructed or run.

**Historical environment:** public MIT code, Elixir `~> 1.14`; recorded CI exercises Elixir/OTP 1.17.1/27.0, 1.19.0/28.5 and 1.20.0/29.0.1. The normal test lockfile is `mix.lock`, unless `LOCKFILE` selects an alternate adapter matrix. The helper starts optional HTTP clients and defines a Mox adapter. The task boundary can use the real middleware and a local recording adapter; no external provider account is necessary. Dependency compilation and helper startup remain unqualified, and the broader adapter suite has additional local HTTP fixtures. Keep its ordinary MIT notice. [Pinned Mix](https://github.com/elixir-tesla/tesla/blob/467ef748f0acd2afa0c82c39827df9965d3d9637/mix.exs), [lock](https://github.com/elixir-tesla/tesla/blob/467ef748f0acd2afa0c82c39827df9965d3d9637/mix.lock), [helper](https://github.com/elixir-tesla/tesla/blob/467ef748f0acd2afa0c82c39827df9965d3d9637/test/test_helper.exs), [license](https://github.com/elixir-tesla/tesla/blob/467ef748f0acd2afa0c82c39827df9965d3d9637/LICENSE).

The inspected SecretString path history contains its introduction only; searches found the subsequent release but no later correction to this capability. That bounded search is not proof of absence of defects.

## Finch #391: pool resizing leaves only live workers registered

**Draft maintenance report:** “After reducing a pool's worker count, requests can still select workers that have already shut down. Make scale-down leave the pool immediately usable with the requested number of live workers for HTTP/1 and HTTP/2, with metrics enabled or disabled.” “Immediately” here means at the return boundary of the synchronous resize operation, not a latency threshold.

Three executable paths coordinate this behavior: `lib/finch/http1/pool.ex`, `lib/finch/http2/pool.ex` and `lib/finch/pool.ex`. The reference performs synchronous unregistering in each protocol's termination path and retains optional metrics cleanup. Existing asynchronous Registry exit cleanup could otherwise conceal the defect before an assertion runs. The shared helper name is incidental; an equivalent repair need not copy it. [Accepted implementation and tests](https://github.com/sneako/finch/commit/7773e91e0cf223966a440b73227393480dd74db2).

**Proposed witnesses:** reproduce the upstream matrix of HTTP/1 versus HTTP/2 and metrics on versus off, start three workers, synchronize on registrations, prevent background Registry cleanup from racing the observation, resize to two, then check the public count and perform a successful request. Verify each remaining registered worker is alive and registrations for a separate pool survive. With metrics enabled, also check removed workers leave no obsolete metrics entries. Avoid asserting a helper name or an arbitrary worker selection order. [Upstream deterministic resize test](https://github.com/sneako/finch/blob/7773e91e0cf223966a440b73227393480dd74db2/test/finch/pool/supervisor_test.exs).

**Plausible incomplete controls:** clean up only HTTP/1; unregister only when a metrics reference exists; delete metrics but leave registration to asynchronous cleanup. Each should leave a specific matrix cell wrong. Upstream's revised idle test explicitly ages state and observes checkout updates instead of racing short sleeps; retain that preservation intent without measuring elapsed time. [Idle-test change](https://github.com/sneako/finch/commit/7773e91e0cf223966a440b73227393480dd74db2).

**Historical environment:** MIT, Elixir `~> 1.15`, normal locked Mix dependencies, including a Git-pinned Credo revision. Historical CI includes OTP 26/Elixir 1.15 and OTP 28.4/Elixir 1.19, so this case does not inherently require OTP 29. Test support uses Bypass and a local Cowboy HTTPS/HTTP2 listener; the global helper allocates a port, releases it and starts that listener, a setup race worth correcting transparently if qualification exposes it. The HTTP/2 test disables certificate verification because the fixture uses a self-signed certificate; this candidate tests pool lifetime, not TLS authentication. No external service or Docker sidecar is required by the added regression's source. [Mix](https://github.com/sneako/finch/blob/da57d0a79ce042e0a93741551a5f56cb432323b7/mix.exs), [lock](https://github.com/sneako/finch/blob/da57d0a79ce042e0a93741551a5f56cb432323b7/mix.lock), [helper](https://github.com/sneako/finch/blob/da57d0a79ce042e0a93741551a5f56cb432323b7/test/test_helper.exs), [server](https://github.com/sneako/finch/blob/da57d0a79ce042e0a93741551a5f56cb432323b7/test/support/http2_server.ex), [license](https://github.com/sneako/finch/blob/da57d0a79ce042e0a93741551a5f56cb432323b7/LICENSE.md).

The earlier [#362](https://github.com/sneako/finch/pull/362) introduced resizing together with a broader metrics change. It is not needed to make #391 a complete repair task, because it is already present in the parent. No later correction to shared cleanup appeared in the inspected path history/search. A future resize-feature reconstruction would need separate review of that broader lineage rather than silently widening this repair.

## Req #337: decompression errors participate in the request pipeline

**Draft clarified repair brief:** “Malformed gzip, Brotli or Zstandard response bodies should produce `Req.DecompressError` through the normal request error path instead of leaking codec crashes. Include the failing format and input bytes, preserve a codec-provided reason when available, and keep successful decompression unchanged.” The named error type and data fields are the intended public result; exact English error text is not necessary.

`lib/req/steps.ex` translates three different codec failure conventions and returns errors into Req's existing step machinery. The new `lib/req/decompress_error.ex` represents the failure. This connects binary processing to pipeline control rather than merely changing a message. The originating error-handling proposal expressly distinguishes returning errors from raising them. [Proposal #335](https://github.com/wojtekmach/req/issues/335), [accepted diff](https://github.com/wojtekmach/req/commit/42eb1ed7b43cef81bcb0b692530bbf7df2153be6).

**Oracle gap and proposed checks:** upstream's new failure tests call `Req.get!` and assert the raised type/message; a repair that directly raises the new exception might satisfy those examples without allowing non-bang callers or error steps to handle it. Add `Req.get` checks for `{:error, exception}` and an installed error step that observes the typed failure. Exercise malformed input for all three available codecs and both gzip header spellings, with retries disabled to isolate the error contract. Preserve valid decompression, successful layered encodings, identity encoding, the configured no-decompression path and existing treatment of unavailable/unknown codecs. For a failure after a successfully decoded outer layer, the proposed contract should explicitly identify the bytes supplied to the failing codec; do not silently demand a different whole-response representation. [Changed tests and existing preservation tests](https://github.com/wojtekmach/req/blob/42eb1ed7b43cef81bcb0b692530bbf7df2153be6/test/req/steps_test.exs), [starting pipeline](https://github.com/wojtekmach/req/blob/d6de27dfa02cc2863adb5fd65232edbe4ed5706e/lib/req/request.ex).

**Plausible incomplete controls:** raise the typed error directly; handle gzip alone; return a typed error for every encoded body. These distinguish the error route, codec coverage and preservation. Do not grade the precise wording of a native codec's diagnostic.

**Historical environment:** Req 0.4.14 parent, Elixir `~> 1.13`; CI pins OTP 24.3.4.10/Elixir 1.13 and OTP 26.1.2/Elixir 1.16. The lock includes Finch 0.18.0, Brotli 0.3.2 and ezstd 1.0.9. Brotli and ezstd are native dependencies, making prepared-image qualification material even though the checks can use a local Plug adapter and require no network server. Preserve the historical optional-dependency conditions instead of silently reducing the task to gzip. The global helper excludes integration tests; qualification must ensure the named new checks actually run. Do not copy CI's `--slowest` timing output into this benchmark's evidence. Apache-2.0 is declared in historical Mix and the README's copyright/license section; this historical tree has no standalone root LICENSE file. [Mix](https://github.com/wojtekmach/req/blob/d6de27dfa02cc2863adb5fd65232edbe4ed5706e/mix.exs), [lock](https://github.com/wojtekmach/req/blob/d6de27dfa02cc2863adb5fd65232edbe4ed5706e/mix.lock), [helper](https://github.com/wojtekmach/req/blob/d6de27dfa02cc2863adb5fd65232edbe4ed5706e/test/test_helper.exs), [CI](https://github.com/wojtekmach/req/blob/d6de27dfa02cc2863adb5fd65232edbe4ed5706e/.github/workflows/ci.yml), [license notice](https://github.com/wojtekmach/req/blob/d6de27dfa02cc2863adb5fd65232edbe4ed5706e/README.md#license).

The inspected error-module history shows its later replacement during the broader streaming redesign, not a corrective commit to this historical implementation. That redesign is not required in this repair's reference. [Replacement commit](https://github.com/wojtekmach/req/commit/0678854f09a1b7e63fda820efeee17289871f0c6).

## Mint #514: IPv6 identities agree across HTTP and proxy representations

**Draft maintenance report with essential policy:** “IPv6 literal hostnames produce malformed Host/authority values, and scoped IPv6 names fail through proxies. Format these identities consistently for direct HTTP/1 and HTTP/2, forward-proxy requests and CONNECT tunnels: bracket IPv6 literals, omit their local zone identifier from HTTP-visible values, and preserve existing ordinary-host, explicit-header and default-port behavior.” Zone omission is stated because it is a behavior choice tested by the accepted change.

Five runtime paths coordinate the wire forms: `core/util.ex`, `http1.ex`, `http2.ex`, `unsafe_proxy.ex` and `tunnel_proxy.ex`. The shared utility is only the reference architecture; tests should observe the emitted request/header frames. The reference differentiates a URI host that must include brackets from a host handed to `URI` for absolute-form serialization. [PR and protocol rationale](https://github.com/elixir-mint/mint/pull/514), [accepted diff](https://github.com/elixir-mint/mint/commit/f5fced56ff5aeb3b59b616f125a22afef4928146).

**Proposed witnesses:** capture HTTP/1 Host and decode HTTP/2 `:authority`; inspect forward-proxy absolute request target plus Host; inspect CONNECT target plus Host. Use plain IPv6, zone forms `%eth0` and `%25eth0`, and both default/nondefault ports. Preserve IPv4, DNS names, caller-provided Host values and existing CONNECT address-versus-hostname behavior. Already-bracketed names deserve an explicit preservation check because the description promises they remain unchanged. The upstream direct-connection tests dial localhost while varying the hostname identity, and proxy tests capture requests locally; no real link-local interface or public IPv6 network is needed for those witnesses. [HTTP/1 tests](https://github.com/elixir-mint/mint/blob/f5fced56ff5aeb3b59b616f125a22afef4928146/test/mint/http1/conn_test.exs), [HTTP/2 tests](https://github.com/elixir-mint/mint/blob/f5fced56ff5aeb3b59b616f125a22afef4928146/test/mint/http2/conn_test.exs), [forward-proxy tests](https://github.com/elixir-mint/mint/blob/f5fced56ff5aeb3b59b616f125a22afef4928146/test/mint/unsafe_proxy_host_header_test.exs), [CONNECT tests](https://github.com/elixir-mint/mint/blob/f5fced56ff5aeb3b59b616f125a22afef4928146/test/mint/tunnel_proxy_connect_test.exs).

**Plausible incomplete controls:** repair HTTP/1 only; bracket literals but retain zones in proxy targets; fix proxy Host while leaving its absolute request target wrong. All are plausible compiling repairs with distinct missing obligations. This task overlaps the broad URL/serialization family already considered in Phoenix, so select it for its protocol coverage rather than treating every path as an independent task.

**Historical environment:** Apache-2.0, Mint 1.10.1 parent, Elixir `~> 1.15`, HPAX 1.1.0 locked. CI lists OTP 24.3/Elixir 1.15.8, OTP 28.1/Elixir 1.19 and OTP 29/Elixir 1.20. Test support supplies local sockets and HTTP/2 frame helpers; the normal test helper excludes Docker proxy tests. The added regressions are local tests rather than the Docker proxy suite. Full-project CI also provisions proxies, httpbin and Caddy, so a blanket “all Mint tests are service-free” claim would be false. Pin the chosen local module set and ensure exclusions do not skip the scored checks. [Mix](https://github.com/elixir-mint/mint/blob/6588c77fc8f03adc9614e1e74dc270bce163d60e/mix.exs), [lock](https://github.com/elixir-mint/mint/blob/6588c77fc8f03adc9614e1e74dc270bce163d60e/mix.lock), [helper](https://github.com/elixir-mint/mint/blob/6588c77fc8f03adc9614e1e74dc270bce163d60e/test/test_helper.exs), [CI](https://github.com/elixir-mint/mint/blob/6588c77fc8f03adc9614e1e74dc270bce163d60e/.github/workflows/main.yml), [license](https://github.com/elixir-mint/mint/blob/6588c77fc8f03adc9614e1e74dc270bce163d60e/LICENSE.txt).

No later change to the shared address utility appeared in the inspected path history. Nearby open HTTP/2 CONNECT-204 work concerns response semantics, not this request-serialization outcome; do not incorporate an unmerged fix or generalize this reference into “all CONNECT behavior is correct.” [Open #535](https://github.com/elixir-mint/mint/pull/535).

## Focused reserve and exclusions discovered during screening

**Mint #496** is a useful focused repair: CONNECT must address the configured destination, while TLS verification/SNI and the origin's HTTP identity use `:hostname`. The source adds loopback proxy/TLS tests with an ephemeral trusted certificate chain, including rejection of a mismatched hostname. Accepting all certificates or using the address as identity cannot satisfy both positive and negative witnesses. Preserve tuple addresses, explicit proxy Host headers and ordinary DNS destinations. One executable implementation path changes; `core/util.ex` changes only its spec. It is a different behavior from #514 but shares proxy machinery, so keep both in one family for leakage/overlap accounting. Its parent already includes HTTPS-proxy support and the tunnel timeout correction. The same public Apache/Mix setup pattern applies, with the earlier Mint 1.9.3 parent and its own lockfile. [Accepted tests and implementation](https://github.com/elixir-mint/mint/commit/d9e1824cf496eb6e616ae949c18ee8927d48b9bf), [historical Mix](https://github.com/elixir-mint/mint/blob/bc24618cb9d3b69dbf0ea7de537802f39bbb6f29/mix.exs), [historical lock](https://github.com/elixir-mint/mint/blob/bc24618cb9d3b69dbf0ea7de537802f39bbb6f29/mix.lock).

## Search scope and remaining gate

Discovery inspected the 60 most recently updated merged PR search results for each of Req, Mint, Finch and Tesla, followed by targeted queries for multipart, body streaming, retries, redirects, decompression, assigns, registry cleanup/resize, SecretString and IPv6/tunnels. Metadata/file lists were screened beyond the final shortlist; detailed implementation/test diffs, accepted commits, discussion and relevant path histories were read for the recommended cases. Historical Mix, locks, CI, helpers and license declarations were read at the selected parents. This was a bounded search, not an exhaustive catalogue, and search-result counts are not eligible-case counts.

The next gate is to turn these outcome sketches into independently reviewed minimal contracts, build exact historical offline fixtures, challenge each reference with the proposed positive and incomplete controls, and then perform the repository's repeatability and blind-solvability procedure. All proposed witnesses remain unexecuted. The four projects broaden the source pool, but they are related HTTP-client ecosystem projects; balance them with application, parsing, data and OTP candidates from the other research reports rather than letting this convenient family dominate the release.
