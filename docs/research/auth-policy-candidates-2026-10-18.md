# Authentication, session state and policy candidate expansion

Research date: 2026-10-18. This pass adds **four projects** to the research pool: Guardian, Pow, AshAuthentication and Ueberauth. Guardian #748 is the strongest coordinated candidate here; Ueberauth #217 is a useful focused reserve. Pow #650 and AshAuthentication #1187 offer different work but have concrete qualification holds. None is admitted or functionally qualified.

The [selection guidelines](../pr-selection-guidelines.md), [admission contract](../case-admission.md), [rejection register](../../cases_rejected/README.md) and earlier October research were read first. No previously rejected or deferred Ecto, Phoenix, LiveView, Plug, Oban, Bandit, Broadway, Absinthe, Livebook or Plausible source is relabeled as new. All checks and incomplete controls below are proposals, not executed evidence. This pass used source/API reads only: no builds, project tests, benchmarks, model attempts or performance measurements.

## Guardian #748: connection-aware verification secrets

[Issue #690](https://github.com/ueberauth/guardian/issues/690) requests choosing a verification key from request context for tenant-specific authentication. The accepted change propagates a connection-aware option through header, session and cookie paths, while distinguishing an absent option from an explicit failed lookup. The latter distinction also changes JWT signing and verification. The accepted commit contains five substantive implementation paths: `lib/guardian/plug.ex`, the three `verify_{header,session,cookie}.ex` modules, and `lib/guardian/token/jwt.ex`. [Accepted source diff](https://github.com/ueberauth/guardian/commit/b1a7c817da9ca6df88fb8617f174d72ecc656c79).

**Draft clarified feature brief:** “Let header, session and cookie verification obtain their secret from a one-argument function of the current connection, including through compiled Plug pipelines. Preserve static secrets and existing MFA resolution. An explicit secret that is or resolves to `nil` must report a missing-secret error rather than use the application secret; an omitted option must retain the existing fallback. Resolve a function only when that entry point has a token, and preserve the separate options of cookie refresh.” Public error naming and invalid-resolver policy should be settled in this brief before scoring them; private helper names need not be required.

| Proposed named witness | Outcome and preservation |
| --- | --- |
| `header and session use this request's key` | Locally generated tokens for tenants A and B succeed under their own connection key and fail under the other key; ordinary static-secret requests continue to work |
| `cookie exchange preserves the selected key` | A locally signed refresh token produces a valid access token under the selected key; the resulting token must actually verify, not merely populate connection assigns |
| `failed lookup cannot become global fallback` | A token signed with the configured global key is rejected when a present resolver returns `nil`; the same token remains valid when the option is absent |
| `MFA semantics remain unchanged` | Existing `{module, function, args}` values receive their original arguments, without an injected connection; a tuple resolving to `nil` fails closed |
| `compiled pipeline and no-token behavior` | A remote function capture survives Plug compilation; requests without a token do not invoke the resolver |
| `cookie refresh has its own options` | Exercise explicit refresh options separately from the initiating plug options, without assuming implicit option inheritance |

The upstream tests already exercise these relationships, including a real `Plug.Builder` pipeline, inherited default secret fetchers and signing/verification public APIs. The strongest added security check deliberately uses a **globally valid** token with `secret: nil`; a token already invalid under the global key would not distinguish the faulty fallback. [Header tests](https://github.com/ueberauth/guardian/blob/b1a7c817da9ca6df88fb8617f174d72ecc656c79/test/guardian/plug/verify_header_test.exs), [cookie tests](https://github.com/ueberauth/guardian/blob/b1a7c817da9ca6df88fb8617f174d72ecc656c79/test/guardian/plug/verify_cookie_test.exs), [JWT tests](https://github.com/ueberauth/guardian/blob/b1a7c817da9ca6df88fb8617f174d72ecc656c79/test/guardian/token/jwt_test.exs).

**Plausible compiling incomplete controls:** support the resolver in all three plugs but retain the old `nil` fallback; alternatively update header verification only. The first should fail the global-token/missing-key witness, the second the session and cookie witnesses. Do not use a missing new helper or an uncompilable partial diff as the control. Check functional outcomes through public entry points rather than requiring the reference helper's internal representation.

**Historical environment.** The parent declares Elixir `~> 1.13`, has `.tool-versions` selecting Elixir 1.18.4/OTP 27.3.4, and locks Plug 1.19.2 and JOSE 1.11.12. CI declares several Elixir/OTP combinations, including 1.18/27; that declaration is not a reproduced build result. `test/test_helper.exs` defines a small local helper and starts ExUnit. This boundary needs local generated keys, cookies and connections, with no identity-provider account, database or browser. The project is MIT licensed. Dependency prefetch and a compatible pinned image still require qualification. [Parent Mix project](https://github.com/ueberauth/guardian/blob/4073c734421cb87f173b666d6e828e273cff6a4d/mix.exs), [tool versions](https://github.com/ueberauth/guardian/blob/4073c734421cb87f173b666d6e828e273cff6a4d/.tool-versions), [lock](https://github.com/ueberauth/guardian/blob/4073c734421cb87f173b666d6e828e273cff6a4d/mix.lock), [helper](https://github.com/ueberauth/guardian/blob/4073c734421cb87f173b666d6e828e273cff6a4d/test/test_helper.exs), [license](https://github.com/ueberauth/guardian/blob/4073c734421cb87f173b666d6e828e273cff6a4d/LICENSE).

**Follow-up screen.** The inspected history for `lib/guardian/plug.ex` and `lib/guardian/token/jwt.ex` contains no later change after #748 as of this research. Searches for secrets and the linked issue found no later correction to this capability. This bounded screen does not establish absence of every possible defect.

## Pow #650: writes complete before callers consume cached state

[Issue #635](https://github.com/pow-auth/pow/issues/635) reports intermittent authentication failure when a just-created token is read before an asynchronous cache write is processed. [Issue #359](https://github.com/pow-auth/pow/issues/359) supplies a password-reset manifestation. The accepted change makes writes synchronous by default in both ETS and Mnesia, retaining an explicit asynchronous mode. It is a correctness task about completion and visibility, with no speed target. [Accepted diff](https://github.com/pow-auth/pow/commit/b8d9f27aca95e012be351a4abedf8248f0bf0f47).

The two backends achieve the same caller contract differently. ETS waits for its owning GenServer to perform mutations. Mnesia mutates the table in the caller and schedules invalidator bookkeeping separately. Grading must therefore allow different ownership designs rather than requiring every backend to use `GenServer.call/2`.

**Draft clarified brief:** “With the default cache configuration, a successful put or delete must be visible to subsequent reads when the operation returns, for both ETS and Mnesia backends. Keep explicit `writes: :async` available, and preserve namespace isolation, batches, expiry and stored-data behavior.” Whether this candidate promises cross-node visibility must be decided explicitly; the tractable first version should identify its single-node boundary rather than claim distributed correctness without a cluster fixture.

**Named proposed witnesses:** `returned put is readable`, `returned delete is absent`, `batch members are all visible`, `namespaces do not interfere`, and `explicit async eventually completes after a controlled processing barrier`. Include an existing unrelated value and both insertion/deletion paths so disabling reads or deleting the whole table cannot pass. Expiry and restart preservation need controlled events or a reviewed clock seam, not sleep-based performance assumptions.

**Oracle hold.** The upstream new asynchronous tests assert that a read immediately following `put` still sees the old state, then sleep and expect the new state. An asynchronous implementation is permitted to finish before that first read; this is a scheduler assumption, not a sound behavioral contract. Conversely, a few ordinary write/read samples may accidentally pass unchanged code. A controlled interleaving that distinguishes early return from completed mutation is needed before this becomes a case. It must accept both caller-owned and server-owned valid mutations. A plausible compiling incomplete control is synchronous puts with deletes still asynchronous, or repairing only ETS. Neither was constructed or executed. [ETS tests](https://github.com/pow-auth/pow/blob/b8d9f27aca95e012be351a4abedf8248f0bf0f47/test/pow/store/backend/ets_cache_test.exs), [Mnesia tests](https://github.com/pow-auth/pow/blob/b8d9f27aca95e012be351a4abedf8248f0bf0f47/test/pow/store/backend/mnesia_cache_test.exs).

**Machine-rule hold.** The changed Mnesia test file also measures node startup elapsed time and compares it with a bound. Do not run that whole upstream file on this machine. A future case must use reviewed functional checks without that performance assertion; distributed startup support is separate work. Watchdogs may detect hangs, but elapsed time must not become correctness or performance evidence.

**Historical environment.** The parent declares Elixir `~> 1.7`; its CI includes Elixir 1.12.0/OTP 24.0 and older combinations. The lock contains Phoenix 1.6.0, Plug 1.12.1 and Postgrex 0.15.10. The common helper creates/migrates PostgreSQL, starts test endpoints, starts Mnesia and launches `epmd` even when selecting a cache test file. Do not label the ordinary upstream invocation service-free. A smaller preparation path would be an attributed fixture change; preserving the normal helper needs a pinned local PostgreSQL instance. Mnesia state must use isolated directories, serialized tests and bounded BEAM resources. The project is MIT licensed. [Parent Mix](https://github.com/pow-auth/pow/blob/17fc320749d05874ab5fd72030e83b657ff7d7bc/mix.exs), [CI](https://github.com/pow-auth/pow/blob/17fc320749d05874ab5fd72030e83b657ff7d7bc/.github/workflows/build.yml), [helper](https://github.com/pow-auth/pow/blob/17fc320749d05874ab5fd72030e83b657ff7d7bc/test/test_helper.exs), [license](https://github.com/pow-auth/pow/blob/17fc320749d05874ab5fd72030e83b657ff7d7bc/LICENSE).

**Later corrections are scope evidence, not an automatic patch bundle.** The backend history includes a Mnesia startup error correction and [#714](https://github.com/pow-auth/pow/pull/714), fixing namespace handling when invalidators are reconstructed after restart. The latter is a real preservation concern if the brief includes restart/expiry across namespaces, but is not evidence that synchronous writes introduced the defect. Resolve that scope and reference challenge explicitly. Importing years of intervening changes would destroy this candidate's compact identity. [Startup correction](https://github.com/pow-auth/pow/commit/d32dbcbf71059b54a3050ec1ad7cdec01bc1a130), [expiry correction](https://github.com/pow-auth/pow/commit/ed17a7172bef023338e33fedcb3ea19153746c8b).

## AshAuthentication #1187: POST callback and same-origin handoff

[Issue #1181](https://github.com/team-alembic/ash_authentication/issues/1181) connects a POST callback routing failure with loss of the browser session in an OAuth flow. The accepted reference expands routing, advertises GET/POST callback methods, and renders an escaped form that submits to the same origin when the original POST has no session. It avoids writing a new session cookie during the intermediate response and prevents repeated reflection. This is an HTTP/browser/state task, distinct from Guardian's key selection. [Accepted diff](https://github.com/team-alembic/ash_authentication/commit/7a5182f08617750c827f6f6c5460af3cd1d3c3d5).

The substantive paths are `plug/router.ex`, `strategies/oauth2/strategy.ex`, `strategies/oauth2/plug.ex`, and `strategies/oauth2/interstitial.html.eex`. The separate `strategy.ex` protocol change is a type declaration, not another implementation path. The template's license sidecar and upgrade documentation are recorded separately.

**Draft brief:** “Support OAuth callback POSTs without changing the application's existing `SameSite=Lax` session-cookie policy. When the cross-site POST lacks the session, preserve the existing browser session and transfer the response parameters through a same-origin POST before completing normal session-bound verification. Keep parameters out of the URL, preserve ordinary GET callbacks, and fail when the handoff still has no valid session.” If the public renderer override or a particular markup convention is required, state that separately; exact HTML and private marker names are not the user outcome.

| Proposed named witness | Required observation |
| --- | --- |
| `callback is actually routable by POST` | Dispatch through the real router and strategy protocol, rather than calling the plug function alone; existing single-method strategies and GET callbacks still dispatch |
| `same-origin handoff retains the initiating session` | A local browser first obtains a session cookie, then receives a form POST from a distinct local site; the intermediate response does not replace that cookie, and the subsequent same-origin request reaches verification with the original session |
| `parameters remain body data` | Benign quotes, ampersands and angle brackets round-trip as field values; they do not alter markup or enter the URL |
| `missing session terminates` | A second handoff without a session reaches the normal failure result rather than another intermediate form |
| `valid and invalid state remain discriminating` | Complete a local successful handshake and reject a mismatched one; a mock that always reports success is insufficient for this boundary |

The upstream tests verify HTML fragments, escaping, the ignore-session flag, the loop guard and phase metadata. They do **not** establish the browser cookie round-trip, and the callback tests bypass the actual router. The local end-to-end fixture should use two distinct local sites and a local provider endpoint, with no Apple account or real credentials. Two ports on the same site are not enough to reproduce a cross-site cookie condition. The current Node/browser adapter needs an explicit server/bootstrap and outcome contract; do not assume arbitrary upstream browser support exists. [Added plug tests](https://github.com/team-alembic/ash_authentication/blob/7a5182f08617750c827f6f6c5460af3cd1d3c3d5/test/ash_authentication/strategies/oauth2/plug_test.exs), [router](https://github.com/team-alembic/ash_authentication/blob/7a5182f08617750c827f6f6c5460af3cd1d3c3d5/lib/ash_authentication/plug/router.ex).

**Plausible incomplete control:** enable POST routing and return the handoff form, but leave an already-dirty session eligible to write a replacement cookie. This should compile and pass fragment checks while failing the browser preservation witness. A routing-only change is another partial solution. The existing test helper's copying of modules through Mimic does not justify replacing the state-verification path with a success stub in the acceptance check.

**Corrected-feature follow-up.** Direct commit [`d7f939c`](https://github.com/team-alembic/ash_authentication/commit/d7f939cd02bd618bcaa304631846fa75ffc419d7) subsequently fixes callback session cleanup on error: rebinding a connection in a `with` head had not updated its `else` branch. That behavior predates #1187; do not claim the POST feature caused it. If the new case requests a complete callback lifecycle, add “consume the stored handshake state on terminal success or failure,” then consider an explicitly attributed #1187-plus-cleanup reference. A hypothetical selected combination has **not** been applied or qualified here. The later [#1205](https://github.com/team-alembic/ash_authentication/pull/1205) adds opt-in IdP-initiated restart behavior; it is a separate capability, not an obligatory repair to #1187. Do not silently combine it. A still later [#1229](https://github.com/team-alembic/ash_authentication/pull/1229) changes OAuth/OIDC configuration; that is another reason not to use the entire chronological interval.

**Historical environment.** Although the parent Mix requirement is `~> 1.13`, its checked-in tool versions select Elixir 1.20.2/OTP 29.0.3. The lock includes Ash 3.29.3, AshPostgres 2.10.0, Plug 1.20.2, and native `bcrypt_elixir`/`argon2_elixir` packages. The `test` alias creates and migrates PostgreSQL; `Example.Repo` declares minimum PostgreSQL 16 and the `ash-functions`, `uuid-ossp` and `citext` extensions. CI delegates to a mutable shared workflow, so that reference alone does not pin the historical build environment. Qualify a compatible image, native build toolchain, dependencies, database extensions and the browser fixture explicitly. Preserve MIT licensing and SPDX/file-sidecar notices. [Tool versions](https://github.com/team-alembic/ash_authentication/blob/7b468bc23395e941eb3942998d896637ee9c9e07/.tool-versions), [Mix](https://github.com/team-alembic/ash_authentication/blob/7b468bc23395e941eb3942998d896637ee9c9e07/mix.exs), [lock](https://github.com/team-alembic/ash_authentication/blob/7b468bc23395e941eb3942998d896637ee9c9e07/mix.lock), [repository configuration](https://github.com/team-alembic/ash_authentication/blob/7b468bc23395e941eb3942998d896637ee9c9e07/test/support/example/repo.ex), [CI](https://github.com/team-alembic/ash_authentication/blob/7b468bc23395e941eb3942998d896637ee9c9e07/.github/workflows/elixir_lib.yml), [license](https://github.com/team-alembic/ash_authentication/blob/7b468bc23395e941eb3942998d896637ee9c9e07/LICENSES/MIT.txt).

## Ueberauth #217: protect state-cookie integrity

This is deliberately a focused reserve rather than an inflated multi-file candidate. [Issue #153](https://github.com/ueberauth/ueberauth/issues/153) requests a signed state cookie; [#217](https://github.com/ueberauth/ueberauth/pull/217) signs it in the request phase and verifies it before callback nonce comparison. The only implementation file is `lib/ueberauth/strategy.ex`; `mix.exs` raises the Plug floor to 1.10 for signed-cookie support. The broader outcome combines origin-authenticated state, caller-supplied state matching and preservation of legitimate provider execution. [Accepted diff](https://github.com/ueberauth/ueberauth/commit/b02dc2d8b72754665f4b90b87d9362e49a18f6b2).

**Draft repair brief:** “For strategies with state protection enabled, require the callback's state cookie to have been issued by this application and to match the returned state parameter. Preserve valid request/callback flows, existing SameSite configuration and strategies that explicitly disable this protection.” Host applications must provide a stable secret across both phases; expose that setup requirement without prescribing the implementation.

**Named witnesses:** `issued cookie completes callback`; `unsigned matching values are rejected`; `modified or wrong-key cookie is rejected`; `missing or mismatched state is rejected`; `already-fetched cookies are still verified`; `valid callback clears the state cookie`; `explicitly disabled protection remains compatible`. Use synthetic local values and a local provider implementation. Assert whether the provider was invoked, not only that a failure assign exists. Keep a positive successful callback alongside every invalid-state group. The upstream tests cover most of this matrix, with both fetched and unfetched cookie states. Avoid requiring one exact exception class for a missing host secret unless the brief explicitly commits to it. [Pinned tests](https://github.com/ueberauth/ueberauth/blob/b02dc2d8b72754665f4b90b87d9362e49a18f6b2/test/ueberauth_test.exs).

**Plausible incomplete control:** generate signed cookies but continue accepting a legacy unsigned cookie when its contents match the parameter. This remains a plausible compatibility shortcut and should fail the named unsigned-cookie witness while retaining normal success. Reject-all callbacks must fail the positive path. Neither control was built.

**Historical environment.** The parent declares Elixir `~> 1.14`, selects Elixir 1.19.5/OTP 28.4.1 in `.tool-versions`, and already locks Plug 1.20.3. Therefore the dependency-floor change should not require a lock upgrade for this pinned case. The helper only starts ExUnit; local provider support enables service-free functional checking. CI declares several versions but is not fresh qualification evidence. MIT license. No later change to `strategy.ex` was found in the inspected history after #217. [Mix](https://github.com/ueberauth/ueberauth/blob/a9fe6cf95b10797eae60cca0ff2cef7fca326c6d/mix.exs), [lock](https://github.com/ueberauth/ueberauth/blob/a9fe6cf95b10797eae60cca0ff2cef7fca326c6d/mix.lock), [tool versions](https://github.com/ueberauth/ueberauth/blob/a9fe6cf95b10797eae60cca0ff2cef7fca326c6d/.tool-versions), [helper](https://github.com/ueberauth/ueberauth/blob/a9fe6cf95b10797eae60cca0ff2cef7fca326c6d/test/test_helper.exs), [license](https://github.com/ueberauth/ueberauth/blob/a9fe6cf95b10797eae60cca0ff2cef7fca326c6d/LICENSE).
