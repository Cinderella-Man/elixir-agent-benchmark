## Original contract and proposed minimal brief

The first-party [PR #37](https://github.com/fly-apps/live_beats/pull/37) requests now-playing information in the page title and Media Session metadata when the browser supports it. Its author explicitly excludes duration/scrubber changes shown incidentally in screenshots. The stated title format includes song title, artist and a now-playing indicator; exact punctuation need only be scored if the final brief specifies it.

**Proposed solver brief, corrected before fixture review:** “Show the currently playing song's title and artist in the browser tab and, where supported, the browser's media-session metadata. Update the information when the song changes, restore the ordinary non-playing tab title when listening stops, and preserve playback in browsers without Media Session support.”

The update-on-song-change and stop-title clauses make ordinary lifecycle behavior explicit. Stop-title restoration is a curator clarification of the proposed task, not a direct quotation of the PR's description. The initial draft said “app-name title”; the parent flagged that as overly specific, and accepted-source inspection confirmed the ordinary profile-list title is `Listing Songs`, with the existing suffix. That correction is recorded rather than treating the original proposal as an upstream requirement. Do not require exact punctuation or restoration of an arbitrary previously visited page's title.

Required outcomes from that brief and the starting source:

1. Playing a real song reaches the browser with its actual title and artist. A server socket assignment alone is insufficient evidence: the title must be observable as `document.title`, and metadata must reach the supported browser Media Session interface.
2. Moving to another real song replaces both title and artist; stale metadata from the first song is incorrect. Do not constrain event names, helper methods or field shape.
3. Stopping listening restores the ordinary non-playing browser title and preserves the existing stop behavior. In a profile-list flow, the starting ordinary title is `Listing Songs` plus the established suffix. Pausing a song is a separate existing operation and need not clear now-playing information.
4. A browser without Media Session still receives a useful tab title and retains ordinary playback. Do not silently require a partial/broken API shape if the scored condition is complete absence of Media Session.
5. Existing play/pause/next/previous control policy, audio URL/token use and ordinary playback continue to work. No new artwork, album, duration, scrubber, OS media-action handlers, playback-state reporting, or metadata clearing on stop is authorized by this brief.

The starting [PlayerLive](https://github.com/fly-apps/live_beats/blob/a94cf610dae100ac0c6a8aa45a1e41ed67f1c93d/lib/live_beats_web/live/player_live.ex) handles song changes and a distinct stop event; the [audio hook](https://github.com/fly-apps/live_beats/blob/a94cf610dae100ac0c6a8aa45a1e41ed67f1c93d/assets/js/app.js) controls an actual audio element. The player is a sticky nested LiveView in the [live layout](https://github.com/fly-apps/live_beats/blob/a94cf610dae100ac0c6a8aa45a1e41ed67f1c93d/lib/live_beats_web/templates/layout/live.html.heex); the [root layout](https://github.com/fly-apps/live_beats/blob/a94cf610dae100ac0c6a8aa45a1e41ed67f1c93d/lib/live_beats_web/templates/layout/root.html.heex) supplies the existing title suffix. Those boundaries require a real browser witness, rather than an isolated JavaScript call or an assertion against a socket assign.

Relevant limits and follow-ups:

- The accepted code does not clear Media Session metadata on stop, reset it on pause, install media action handlers, or report playback state/position. Those are not hidden requirements. Native platform presentation is browser/platform-dependent under the [Media Session specification](https://w3c.github.io/mediasession/#metadata); reading the real `navigator.mediaSession.metadata` after application interaction is a suitable browser boundary without demanding a particular OS control panel.
- The embedded player's owner control is pause, but the containing [ProfileLive title bar](https://github.com/fly-apps/live_beats/blob/a94cf610dae100ac0c6a8aa45a1e41ed67f1c93d/lib/live_beats_web/live/profile_live.ex) also provides `Stop Listening` whenever that profile is active, including one's own profile. This corrects the initial review's overly broad listener-only caution; the title-bar stop action is valid. Later [44f86837](https://github.com/fly-apps/live_beats/commit/44f86837f1449c39fa9fa71223b14921597e53c4) changes no-profile controls and initial profile choice; do not import those newer behaviors.

- The containing ProfileLive still assigns titles during route actions. Keeping now-playing text through unrelated navigation, initializing metadata when joining an already-paused song, and handling rejected autoplay are broader lifecycle questions not resolved by the original PR.
