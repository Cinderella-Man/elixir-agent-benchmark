# Core pilot fixture review

Authored 2026-10-11. These are two small repository-repair controls for establishing the end-to-end harness. They are **not** sufficient to rank the models or demonstrate sustained application-building ability. Neither is a claimed historical upstream bug: each starts from a pinned working open-source repository and introduces an intentional, plausible regression.

| Case | Pinned source | Work exercised | Independent acceptance coverage |
|---|---|---|---|
| `core-nimble-normalization` | [NimbleOptions](https://github.com/dashbitco/nimble_options/tree/825c05837f236c612c6ac2855735ec6cf7f2be69), version 1.1.1, Apache-2.0 | Inspect recursive validation, understand custom-validator contracts, fix loss of normalized data through map boundaries, write regression tests | Six tests cover top-level map defaults, typed map key and value conversion, nested list-of-map composition and order, empty/idempotent input, invalid custom values, unknown/missing nested keys |
| `core-genstage-cancelled-demand` | [GenStage](https://github.com/elixir-lang/gen_stage/tree/73957a6479cd4ec392834a2fa418bc32ea7e7fbc), version 1.3.2, Apache-2.0 | Follow demand through actual producer/consumer processes and cancellation, preserve in-flight credit and back-pressure, add lifecycle regressions | Four tests cover replacement demand below/above outstanding credit, unaffected concurrent subscriptions, multiple cancellation plus buffering, and idle cancellation |

Each case contains `case.json`, an agent-facing `ticket.md`, `starter.patch`, `reference.patch`, and grader-only `hidden_test.exs`. The starter applies to the source revision. The reference applies **after** the starter. Tickets describe observable application failures and the expected contract, without naming the implementation line to reverse. Acceptance tests assert public outcomes rather than patch text or private dispatcher tuples. The full existing upstream suite is also required, and the grader must restore the original tracked tests before grading so disabling tests cannot earn a pass.

The hidden cases were authored independently of the public dataset's solutions and test harnesses. Their relationship to the dataset is concept-only: structured-data validation and OTP lifecycle work. No exact numbered family is claimed. The [source dataset pin](https://github.com/Cinderella-Man/elixir-sft-dataset/tree/328195bb34782b61fdad8df8188dffa86bc5defe/tasks) is recorded for provenance; no dataset source code is redistributed by these fixtures.

The requested runtime is `elixir:1.18.4-otp-27`, `MIX_ENV=test`, with `mix deps.get`, `mix deps.compile` and `mix compile` during online environment preparation, followed by offline `mix test --seed 0`. NimbleOptions declares Elixir `~> 1.15` and locked test dependencies on ExCoveralls/CAStore; GenStage declares `~> 1.11` and has no dependencies selected in the test environment. These compatibility claims come from source inspection. The orchestrator must record the resolved container digest, actual Elixir/OTP versions, and exact dependency lock alongside each run; the image tag itself is not an immutable pin.

The GenStage grader uses supervised processes, unique subscription references and synchronous call barriers from the same consumer that sent the preceding ask/cancel message. It does not sleep or assert elapsed time. The 1,000 ms receive bounds detect hangs or missing messages only; they are not performance evidence. The supervised processes are cleaned up between tests. Async ExUnit execution does not share named processes or global application state.

## Validation status

Subsequent rig validation completed for both cases: the broken state fails, the reference passes hidden and original suites, and an early-exit bypass is rejected. See the [executed controls and model attempts](pilot-results.md). The paragraph below records the earlier authoring checkpoint.

Local source inspection and `git apply --check` verified both starter patches against their pins and both reference patches against their starter states. No Elixir suites, model inference or performance measurements were run on the shared workstation while authoring these fixtures. Runtime acceptance remains pending the orchestrator's isolated validation on the authorized rig. A usable case must show: clean source passes, starter fails for the intended assertions, and starter plus reference passes both hidden acceptance and the upstream regression suite. Preserve those outcomes and reject a case from scoring if this contract fails.

These deliberately small repairs provide a clear initial calibration. Expand the eventual scored suite with multi-module feature work, Phoenix/Ecto/LiveView behavior, failure recovery, tests the agent must discover, and three-ticket sequences. Do not interpret success on these controls as evidence that one model is better at all Elixir work.
