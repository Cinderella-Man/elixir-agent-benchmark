## Candidate evidence and acceptance boundaries

### #6300 — weekday matching in short year-over-year comparisons

Merged 2026-05-04. The report says `match_day_of_week` was ignored for year-over-year comparisons of `day` and `24h` periods. The merged production delta is confined to `lib/plausible/stats/comparisons.ex`: the two short-period paths now apply the weekday option using dates in the site's timezone and shift both endpoints consistently. The PR relates the today regression to [#6205](https://github.com/plausible/analytics/pull/6205); that relationship is the author's account, not independent reproduction here. [Report and repair](https://github.com/plausible/analytics/pull/6300), [merged production source](https://github.com/plausible/analytics/blob/dcb92e5cc5493f4d778df726371336d376e799a2/lib/plausible/stats/comparisons.ex).

The upstream additions in `test/plausible/stats/comparisons_test.exs` cover today with the option off, today with it on in UTC and US/Eastern, and the preceding 24h window with it on. Inputs supply fixed `now` values; the UTC example compares Wednesday 2023-03-15 to Wednesday 2022-03-16. These use the real query/comparison domain APIs with `DataCase`, without an enterprise-only tag on the added cases. Expected before/after distinction: the parent keeps the wrong weekday for the enabled option; the repair respects it while retaining the option-off control. [Pinned upstream tests](https://github.com/plausible/analytics/blob/dcb92e5cc5493f4d778df726371336d376e799a2/test/plausible/stats/comparisons_test.exs).

Proposed acceptance: retain those exact timezone and option controls; assert both endpoints and duration, not only the first date. Use a frozen `now` and pinned timezone data. A natural ticket can describe the wrong comparison dates without identifying the implementation branch. Existing-suite health and the test overlay's before/after result remain unverified.

The patch introduces `add_site_guest_or_team_member/2` in `test/support/teams/test.ex`; the evaluator must include that helper or equivalent fixture setup. Relevant assertions are not `ee_only`, although unrelated DNS behavior and tests in the module have edition-specific setup. Expected before/after distinction: editor workflows cannot complete at the parent and can persist the change at the repair; the previously supported roles remain controls. [Pinned tests](https://github.com/plausible/analytics/blob/c4ea07d8bc38deacb7c6291ff073bcf814f113f8/test/plausible_web/live/change_domain_test.exs), [support helper](https://github.com/plausible/analytics/blob/c4ea07d8bc38deacb7c6291ff073bcf814f113f8/test/support/teams/test.ex).

### #6763 — visitors CSV with a page filter and no legacy cutoff

Merged 2026-10-09. On a site with `legacy_time_on_page_cutoff: nil`, a page-filtered dashboard export could raise an Ecto query error when producing `visitors.csv`. The export asks for a time dimension; the fallback in `lib/plausible/stats/query_optimizer.ex` enabled a legacy time-on-page metric even when that metric could not be merged for those dimensions. The single-line production repair applies the existing eligibility predicate to that fallback. [Public report](https://github.com/plausible/analytics/pull/6763), [merged optimizer](https://github.com/plausible/analytics/blob/bc2c7b395caddf7bb4eec2548be7958824d07d4a/lib/plausible/stats/query_optimizer.ex).

The new case in `test/plausible_web/controllers/api/stats_controller/dashboard_csv_export_test.exs` updates the site's cutoff to nil, populates `/blog` pageviews and engagement at fixed dates, requests a seven-day page-filtered export, extracts `visitors.csv`, and checks the headers, visitor rows and empty time-on-page column. This goes through the controller and analytics query path. It is not marked enterprise-only. The author reports that this test failed when the production fix was reverted and that the test file passed with the fix; this is upstream author-reported evidence, not our CE validation. [Pinned regression test](https://github.com/plausible/analytics/blob/bc2c7b395caddf7bb4eec2548be7958824d07d4a/test/plausible_web/controllers/api/stats_controller/dashboard_csv_export_test.exs), [author's validation report](https://github.com/plausible/analytics/pull/6763).

Proposed acceptance uses that real export path, preserves supported legacy-metric cases, and checks ordinary CSV values as well as successful response status. Expected before/after distinction: the added nil-cutoff combination reaches the invalid query on the parent and returns the specified CSV after repair. The ticket should report the export failure and relevant site state; it need not disclose the optimizer or predicate.

### #6449 — shared-link association validation and immutable slug

It stops directly casting `slug` and `segment_id`; domain operations validate segment identifiers against the link's site, and the LiveComponent delegates updates to that operation. Invalid or foreign segment identifiers resolve to no segment. **The PR body is stale.** It describes restricting links to site-type segments, but the final commit deliberately allows any segment belonging to the same site. The final test explicitly retains a segment that was attached as a site segment and later changed to personal. Use the merged tests and final behavior, not the earlier type restriction, in the ticket and oracle. [PR description](https://github.com/plausible/analytics/pull/6449), [final PR commit](https://github.com/plausible/analytics/commit/2ba6a2a3f98dd5e5bfac8f41b72649247117198d), [pinned tests](https://github.com/plausible/analytics/blob/63929d339231e107c5eda8b4499250ea16246a6d/test/plausible_web/live/shared_link_settings/form_test.exs).

Six added LiveView/Ecto tests cover attaching a valid same-site segment, clearing it, rejecting a foreign segment during creation and editing, retaining the now-personal same-site segment, and refusing a submitted slug replacement. Several positive cases are controls, not intended parent failures. The meaningful expected failures are foreign associations and mutable slug. The module has no enterprise-only tag; its growth-plan helper inserts a local subscription fixture, and SharedLinks/SiteSegments are common feature definitions. [Regression tests](https://github.com/plausible/analytics/blob/63929d339231e107c5eda8b4499250ea16246a6d/test/plausible_web/live/shared_link_settings/form_test.exs), [team fixture helper](https://github.com/plausible/analytics/blob/63929d339231e107c5eda8b4499250ea16246a6d/test/support/teams/test.ex), [feature definitions](https://github.com/plausible/analytics/blob/63929d339231e107c5eda8b4499250ea16246a6d/lib/plausible/billing/feature.ex).

Proposed acceptance preserves the full valid/invalid input matrix through real form submission and asserts persisted rows. It must include both create and update paths and preserve a link's existing slug. This is one validation-boundary case with two consequences; state both in its ticket rather than hiding one requirement in grading.

Do not cite an unseen issue as independent evidence or require the obsolete mechanism. [PR description and review](https://github.com/plausible/analytics/pull/6441), [final goal planning source](https://github.com/plausible/analytics/blob/37e352c73dc586314a43985a81371df895ed6c14/lib/plausible/stats/goals.ex).

Expected before/after distinction: a constrained query crashes or includes unsupported imported contributions on the parent; the repair supplies native-only results for those goals while retaining eligible imported results. CE API-key and feature fixtures still require execution qualification.

[Merged patch](https://github.com/plausible/analytics/commit/121ef8de14f0d4fec0c78c465833c4b8351655e7), [CE tracker source](https://github.com/plausible/analytics/blob/121ef8de14f0d4fec0c78c465833c4b8351655e7/lib/plausible_web/tracker.ex).

[CE cache tests](https://github.com/plausible/analytics/blob/121ef8de14f0d4fec0c78c465833c4b8351655e7/test/plausible/site/tracker_script_cache_test.exs), [generic cache tests](https://github.com/plausible/analytics/blob/121ef8de14f0d4fec0c78c465833c4b8351655e7/test/plausible/cache_test.exs), [HTTP tracker tests](https://github.com/plausible/analytics/blob/121ef8de14f0d4fec0c78c465833c4b8351655e7/test/plausible_web/tracker_test.exs).
