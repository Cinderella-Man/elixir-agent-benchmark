# Historical Livebook runtime research

Source and registry inspection, 2026-10-11. This note does not claim that any image builds or any case passes. No application tests, model runs, benchmarks or performance measurements were executed during this research. Runtime qualification belongs on the authorized `ratx570` rig.

## Proposed profile

Use the historical source archive and untouched `mix.lock`, `MIX_ENV=test`, the ordinary Mix target, and a writable unprivileged home/workspace. Install `build-essential`, `git`, `ca-certificates`, `cmake`, `python3` and `bash` on the Debian/Ubuntu images; the last two are harness conveniences. Prepare Hex/Rebar, run `mix deps.get --only test`, `mix deps.compile`, then `mix compile`. Dependency acquisition and native-artifact downloads happen during image preparation; attempts and grading run with external networking disabled and working loopback. Record the resolved image, dependency lock, native artifacts and environment recipe in preparation metadata.

No database sidecar, Node build, browser or release build is needed for these selected Elixir/LiveView paths. Upstream CI runs its Elixir tests before installing Node, and its release Dockerfile copies committed `static/` and `iframe/priv/static/iframe/` assets. Keep those directories, `proto/lib/`, `README.md`, config and test support in the image. The newer `compile.livebook_priv` compiler compresses and copies committed assets itself. These are source-based setup conclusions pending build confirmation. [Older CI](https://github.com/livebook-dev/livebook/blob/5ee9a502af29daa8b499a5e0aba7c36f169968e6/.github/workflows/test.yml), [newer CI](https://github.com/livebook-dev/livebook/blob/bdb2b95a1d7fe837cd71e17688791d4785bb37e9/.github/workflows/test.yml), [Dockerfile](https://github.com/livebook-dev/livebook/blob/bdb2b95a1d7fe837cd71e17688791d4785bb37e9/Dockerfile), [asset compiler](https://github.com/livebook-dev/livebook/blob/bdb2b95a1d7fe837cd71e17688791d4785bb37e9/lib/mix/tasks/compile.livebook_priv.ex).

## Distribution and offline operation

- **#2219 and #2527:** leave `ELIXIR_ERL_OPTIONS` unset. Their app starts `epmd -daemon` and registers its node. Set `LIVEBOOK_DISTRIBUTION=name` and `LIVEBOOK_NODE=livebook@127.0.0.1` to use an explicit loopback long name in the isolated container. This is supported configuration, not a source patch. Each fresh container has its own network namespace. [#2219 startup](https://github.com/livebook-dev/livebook/blob/64dad900d7890389f6f59edf4d6dbbdb725bcb26/lib/livebook/application.ex), [#2527 startup](https://github.com/livebook-dev/livebook/blob/57ddb291598b4ac5683fd71bd7a1454b621091e4/lib/livebook/application.ex).
- **#2663:** leave `ELIXIR_ERL_OPTIONS` and `LIVEBOOK_EPMDLESS` unset. Its default app startup starts epmd and chooses a random long name on `127.0.0.1`. Its optional epmdless mode requires three Erlang flags and changes test exclusions; do not enable it just for this markdown case. [Startup](https://github.com/livebook-dev/livebook/blob/6f7a8e3e79db9a002b5c2508d817402b7c11ccb5/lib/livebook/application.ex), [helper](https://github.com/livebook-dev/livebook/blob/6f7a8e3e79db9a002b5c2508d817402b7c11ccb5/test/test_helper.exs).
- **#2800 and #2822:** set `ELIXIR_ERL_OPTIONS=-epmd_module Elixir.Livebook.EPMD`, as upstream CI does. Startup validates the argument and aborts without it. The custom EPMD module tolerates an absent OS epmd daemon; the app chooses a random loopback long name. **#3076** accepts the same setting; on OTP 27.2+ its fallback can also configure the EPMD module through `:kernel`. [#2822 startup](https://github.com/livebook-dev/livebook/blob/5ee9a502af29daa8b499a5e0aba7c36f169968e6/lib/livebook/application.ex), [custom EPMD](https://github.com/livebook-dev/livebook/blob/5ee9a502af29daa8b499a5e0aba7c36f169968e6/lib/livebook/epmd.ex), [#3076 startup](https://github.com/livebook-dev/livebook/blob/bdb2b95a1d7fe837cd71e17688791d4785bb37e9/lib/livebook/application.ex).
- The historical test helpers use the embedded runtime and start its node manager explicitly. Endpoint `server: false` avoids a public web listener; Bypass still opens local HTTP listeners for S3/session tests. These need working loopback, not outside network access or AWS credentials. The updater is disabled when compiled in test mode. Keep `TEAMS_PATH`, `TEST_FLY_API_TOKEN`, `TEST_GIT_SSH_KEY` and real Livebook credentials absent. Also do not create `../teams`: its existence activates the separate Teams application setup. [Test config](https://github.com/livebook-dev/livebook/blob/bdb2b95a1d7fe837cd71e17688791d4785bb37e9/config/test.exs), [test helper](https://github.com/livebook-dev/livebook/blob/bdb2b95a1d7fe837cd71e17688791d4785bb37e9/test/test_helper.exs), [Teams detection](https://github.com/livebook-dev/livebook/blob/bdb2b95a1d7fe837cd71e17688791d4785bb37e9/test/support/integration/teams_server.ex), [updater](https://github.com/livebook-dev/livebook/blob/5ee9a502af29daa8b499a5e0aba7c36f169968e6/lib/livebook/update_check.ex).

## Portability and qualification hazards

1. **Noble UID collision:** the #3076 amd64 image's Ubuntu base-layer `/etc/passwd` was inspected read-only and contains `ubuntu:x:1000:1000:Ubuntu:/home/ubuntu:/bin/bash`. Reuse or rename that account before making the harness's agent account; unconditional `useradd -u 1000` fails. This was inspected under platform manifest `sha256:e9f6d1f99a696b71fcf49f3eeb86dbb064b98ddee01526ce06010b92e4af088d`, obtained from the registry metadata cited above.
2. **Native test dependencies:** #3076 locks Pythonx 0.4.4 and LazyHTML 0.1.0. Both download native artifacts during dependency compilation or fall back to a C++17 compiler. LazyHTML's fallback additionally needs CMake and retrieves Lexbor v2.4.0. Keep network acquisition in preparation and record its outputs. Pythonx application startup only initializes Python when explicitly configured; the #3076 helper does not do so. Its unrelated evaluator test file does call `Pythonx.uv_init` in `setup_all`, so selecting that file would need a separately prepared Python environment. [Lockfile](https://github.com/livebook-dev/livebook/blob/bdb2b95a1d7fe837cd71e17688791d4785bb37e9/mix.lock), [Pythonx compilation](https://github.com/livebook-dev/pythonx/blob/v0.4.4/mix.exs), [Pythonx startup](https://github.com/livebook-dev/pythonx/blob/v0.4.4/lib/pythonx/application.ex), [LazyHTML fallback](https://github.com/dashbitco/lazy_html/blob/v0.1.0/Makefile), [newer evaluator setup](https://github.com/livebook-dev/livebook/blob/bdb2b95a1d7fe837cd71e17688791d4785bb37e9/test/livebook/runtime/evaluator_test.exs).
3. **Writable scratch state:** historical startup/tests create and clear `tmp/livebook_data/test`, log files, temporary notebooks and bytecode. Fresh sandboxes must own these paths; do not share a data directory across attempts. #3076 removes data at application startup, while older revisions do it in test config. [Older config](https://github.com/livebook-dev/livebook/blob/5ee9a502af29daa8b499a5e0aba7c36f169968e6/config/test.exs), [newer startup](https://github.com/livebook-dev/livebook/blob/bdb2b95a1d7fe837cd71e17688791d4785bb37e9/lib/livebook/application.ex).
4. **Diagnostics depend on compiler version:** retain exact historical Elixir/OTP for evaluator tests. #2800's applicable fixed commit is `3470f2de4878efe15de76193134ad9dbbef5dc43`, whose parent is the specified broken SHA; another branch contains a different commit with the same PR title. Do not select the duplicate by grep alone. [Applicable commit](https://github.com/livebook-dev/livebook/commit/3470f2de4878efe15de76193134ad9dbbef5dc43), [duplicate branch commit](https://github.com/livebook-dev/livebook/commit/01af89d2f11e8c012975bb1b449bcee32726ccb1).

No source adaptation is proposed by this research. Image packages, supported runtime environment settings, full committed assets, historical helper exclusions and fresh writable directories should be enough to attempt qualification. Any later change to source or test support needed for compatibility must be published separately from the defect and reference repair, applied identically to broken/fixed runs, and checked not to conceal the target behavior.
